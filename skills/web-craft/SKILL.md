# Web Craft

Establish the requested outcome, **mode** (discuss, audit, plan, change, verify), and **depth** (quick, focused, deep) from the conversation. Read [working contract](references/working-contract.md). Depth never grants permission to edit. Preserve explicit no-change constraints, while proceeding with already-authorized fixes without redundant confirmation.

Use the existing product and its frequent journeys as the unit of work. Identify what the user does, what must survive interruption, and which environments matter. Do not impose an iOS visual skin on desktop or add APIs merely because they exist.

## Route only what the task needs

| Request | Read |
|---|---|
| Find what feels broken or unfinished | [Web Craft Audit](../web-craft-audit/SKILL.md) |
| Improve a complete task or navigation path | [Web Craft Flows](../web-craft-flows/SKILL.md) |
| Springs, gesture handoff, timing, frame pacing | [Web Craft Motion](../web-craft-motion/SKILL.md) |
| Safari/WebKit, mobile APIs, haptics, installed mode | [Web Craft Browser](../web-craft-browser/SKILL.md) |
| Editing, focus, typography, component states, tiny details | [Web Craft Polish](../web-craft-polish/SKILL.md) |
| Validate an implementation or readiness claim | [Web Craft Verify](../web-craft-verify/SKILL.md) |

These sibling skills are part of this collection. Read their files directly as needed; do not spawn agents merely because multiple skills apply. If a sibling is missing, disclose the missing part and continue with available guidance rather than inventing its contents.

For broad orientation, read the relevant sections of the [rulebook](references/rulebook.md). For overlooked details, consult [microdetails](references/microdetails.md). Use [prompt recipes](references/prompt-recipes.md) when the user wants reusable instructions or staged work. Do not load every reference for a small task.

Prioritize lost work, unusable input, accessibility, delayed response, and unstable geometry before decorative materials. State what was observed versus inferred, and finish with the actual result and meaningful verification gaps. Keep proposed tuning distinct from measured results and Apple-specific evidence.
